# Сравнительный анализ методов тестирования ПО

## 1. Общая характеристика подходов
В процессе разработки и обеспечения качества ПО не существует универсального метода, используя который можно выявить все классы ошибок, без использования сторонних инструментов. Выбор стратегии тестирования зависит от этапа разработки, сложности архитектуры проекта и доступности исходного кода. В рамках ЛР №4 для системы анализа квадратных матриц применялся комбинированный подход, сочетающий структурное, функциональное и статическое тестирование.

## 3. Практические выводы и рекомендации для проекта
1. **Принцип тестовой пирамиды:** основу тестового набора должны составлять быстрые модульные тесты **«белого ящика»** (в исходном проекте 19 юнит-тестов, обеспечивших 88% покрытия операторов и проверку всех ветвлений `try/except`).
2. **Контроль стыков модулей:** для проверки взаимодействия независимых компонентов (`input_module` -> `process_module` -> `output_module`) оптимален метод **«серого ящика»**, позволяющий валидировать структуру JSON-файлов (`matrix.json`, `results.json`) без привязки к внутренним переменным функций.
3. **Автоматизация регрессии:** сочетание статического анализа (`flake8`) и регрессионных тестов в CI/CD (GitHub Actions) позволяет сократить время обнаружения дефектов до нескольких секунд и гарантирует стабильность кодовой базы при дальнейшем развитии проекта.
