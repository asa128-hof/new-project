# Тестирование
# Документация по тестированию ПО (ЛР №4)

## 1. План тестирования
* **Объект тестирования:** Интегрированная система анализа квадратных матриц (`src/main.py`, `src/input_module.py`, `src/process_module.py`, `src/output_module.py`).
* **Цель тестирования:** Проверка корректности работы всех модулей, их взаимодействия через протокол JSON v2.0, а также устойчивости к некорректному вводу и ошибкам файловой системы.
* **Методы тестирования:**
  * Модульное тестирование (Unit Testing) методами «белого ящика» (покрытие операторов, решений, условий и комбинаторное покрытие).
  * Интеграционное тестирование сквозного взаимодействия модулей (`input -> process -> output`).
  * Статический анализ исходного кода с помощью линтера `flake8`.
* **Инструменты:** Python 3.10, `pytest`, `pytest-cov`, `flake8`.
* **Критерии приёмки:** 100% успешное прохождение всех автотестов, покрытие операторов исходного кода не менее 70%, отсутствие ошибок линтера.

## 2. Описание тестовых сценариев
* **Сценарии для `input_module` (6 тестов):**
  * Ввод корректной матрицы 2х2 и проверка создания валидного файла `matrix.json`.
  * Граничные и некорректные значения размерности `n` (`0`, `-5`, `"abc"`, пустая строка).
  * Ввод нечислового значения элемента матрицы (проверка перехвата `ValueError`).
  * Имитация аппаратной/системной ошибки записи на диск (проверка перехвата `IOError`).
* **Сценарии для `process_module` (6 тестов):**
  * Обработка отсутствующего (`FileNotFoundError`) и синтаксически повреждённого (`JSONDecodeError`) файла `matrix.json`.
  * Расчёт количества нулей выше и ниже главной и побочной диагоналей для матрицы 3х3.
  * Граничные случаи: матрица без нулевых элементов, а также матрицы размерностей 1х1 и 2х2.
* **Сценарии для `output_module` (3 теста):**
  * Обработка отсутствующего и повреждённого файла результатов `results.json`.
  * Чтение валидного `results.json` и проверка форматированного вывода всех 4 показателей в консоль.
* **Сценарии для главного модуля `main` (3 теста):**
  * Повторный запрос ввода при ошибке в `input_module` и штатный выход по команде `"нет"`.
  * Корректная обработка аварийного прерывания программы пользователем (`KeyboardInterrupt` / `Ctrl+C`).
  * Многократный запуск рабочего цикла подряд по команде `"да"` с перезаписью результатов.
* **Сквозной интеграционный сценарий (1 тест):**
  * Полный цикл работы системы от консольного ввода матрицы 2×2 до генерации `matrix.json`, расчёта `results.json` и вывода итогов на экран.

## 5. Баг-репорты по выявленным дефектам

### BUG-01: Отсутствие изоляции тестовых данных и пути импорта в `tests/test_main.py`
* **Описание:** При запуске интеграционного теста из корня проекта возникала ошибка импорта модулей из `src/` на CI-сервере (`ModuleNotFoundError`), а промежуточные файлы `matrix.json` и `results.json` перезаписывали рабочие данные проекта.
* **Шаги воспроизведения:** Запустить `pytest tests/test_main.py` в чистом окружении без настройки `PYTHONPATH`.
* **Ожидаемое поведение:** Успешный импорт модулей, работа с временными JSON-файлами без засорения рабочей директории.
* **Фактическое поведение:** Ошибка импорта `ModuleNotFoundError` и создание временных файлов в корне репозитория.
* **Тяжесть / Приоритет:** Major / High (Исправлено: добавлена фикстура `tmp_path` и переменная `PYTHONPATH=src` в CI).

### BUG-02: Нарушения стандарта оформления кода PEP 8
* **Описание:** При статическом анализе выявлены нарушения форматирования (`W291`, `W293`, `E261`, `E302`, `E305`).
* **Шаги воспроизведения:** Выполнить `python -m flake8 src/ --max-line-length=120`.
* **Ожидаемое поведение:** Отсутствие предупреждений линтера (код возврата 0).
* **Фактическое поведение:** Вывод списка стилистических предупреждений во всех 4 модулях `src/`.
* **Тяжесть / Приоритет:** Minor / Low (Исправлено с помощью `autopep8`, повторная проверка прошла чисто).

### BUG-03: Отсутствие валидации пустого массива в `process_module.py`
* **Описание:** При передаче корректного JSON-файла, содержащего пустой список `[]` или неквадратную матрицу, функция `run()` не проверяет корректность размерности перед обращением к `matrix[i][j]`.
* **Шаги воспроизведения:** Записать `[]` или `[]` в `matrix.json` и вызвать `process_module.run()`.
* **Ожидаемое поведение:** Перехват некорректной структуры данных, вывод сообщения об ошибке и возврат `False`.
* **Фактическое поведение:** Возникновение необработанного исключения `IndexError`.
* **Тяжесть / Приоритет:** Minor / Medium (Зафиксировано в бэклог рефакторинга для следующей версии).
