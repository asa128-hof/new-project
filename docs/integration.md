# Документация интеграции модулей

## 1. Описание архитектуры взаимодействия
Взаимодействие модулей организовано по **Т-образной схеме** с использованием нисходящей стратегии интеграции. Главный модуль-диспетчер (main.py) осуществляет последовательный вызов функциональных компонентов нижнего уровня:
1. `input_module.py` – Инициализация и валидация матрицы.
2. `process_module.py` – Расчёт количества нулевых элементов.
3. `output_module.py` – Форматированный вывод рез-ов.

Прямые вызовы функций между подчинёнными модулями отсутствуют. В качестве транспортного протокола выбран **обмен через структурированные текстовые файлы формата JSON**.

## 2. Схема потоков данных (Data Flow)
```text
 [ Пользователь ] ----> (Ввод n, элементов) ----> [ input_module.py ]
                                                          |
                                                  (Запись JSON)
                                                          v
                                                 [ matrix.json ]
                                                          |
                                                  (Чтение JSON)
                                                          v
                                                [ process_module.py ]
                                                          |
                                                  (Запись JSON)
                                                          v
                                                 [ results.json ]
                                                          |
                                                  (Чтение JSON)
                                                          v
                                                [ output_module.py ] ----> (Вывод в консоль) ----> [ Пользователь ]
```

## 3. Описание протоколов, форматов и сопоставление данных (Mapping)
Для передачи данных по транспортному каналу внутренние структуры данных Python транслируются в формат JSON с преобразованием стилей именования полей (из *snake_case* во внешний протокол *camelCase*).

### Таблица соответствия полей (Mapping) для результатов:

| Внутр.переменная (Python) | Поле в транспортном протоколе (JSON) | Тип данных                                  | Описание                         |
| :---                      | :---                                 | :---                                        | :---                             |
| `matrix`                  | Массив массивов (двумерный список)   | `Array (Number)`                            | Квадратная матрица дробных чисел |
| `above_main`              | `aboveMainZerosCount` | `Integer`    | Кол-во нулей строго выше главной диагонали  |                                  |
| `below_main`              | `belowMainZerosCount` | `Integer`    | Кол-во нулей строго ниже главной диагонали  |                                  |
| `above_side`              | `aboveSideZerosCount` | `Integer`    | Кол-во нулей строго выше побочной диагонали |                                  |
| `below_side`              | `belowSideZerosCount` | `Integer`    | Кол-во нулей строго ниже побочной диагонали |                                  |

## 4. Примеры запросов и ответов (файлов обмена)

### Пример входного сообщения (`matrix.json`):
```json
[
    [1.0, 0.0, 3.0],
    [0.0, 5.0, 0.0],
    [7.0, 8.0, 0.0]
]
```

### Пример выходного сообщения (`results.json`):
```json
{
    "aboveMainZerosCount": 2,
    "belowMainZerosCount": 1,
    "aboveSideZerosCount": 1,
    "belowSideZerosCount": 2
}
```
